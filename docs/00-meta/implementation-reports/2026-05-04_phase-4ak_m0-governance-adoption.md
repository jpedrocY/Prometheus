## 2. Triggering Context

### 2.A Phase 4aj's recommendation

Phase 4aj — M0 Governance Reconciliation Memo — was merged to
`main` on `3ad5cc8` after the Phase 4ai cross-sectional feasibility
null. Phase 4aj recommended:

```text
Primary: merge Phase 4aj into main, then remain paused.

Conditional governance: if the operator wants further forward
motion, authorize a future docs-only Phase 4ak M0 governance
adoption phase that decides whether to adopt the revised twelve-
clause M0 gate (Phase 4aj §8) and the post-null cooldown rule
(Phase 4aj §9) as binding governance.
```

### 2.B Phase 4ai's `NOT_SUPPORTED` verdict

Phase 4ai (analysis-and-docs) tested the cross-sectional trend /
relative-strength symbol-selection lane against predeclared
falsification criteria and returned `NOT_SUPPORTED`. The verdict
reinforced two project-level lessons that Phase 4aj operationalized
into the revised twelve-clause M0:

- **opportunity-rate viability ≠ edge-rate viability** (the central
  C1 lesson);
- **structural distance from prior rejections is necessary but not
  sufficient** — a candidate can satisfy every Phase 4m / 4t / Phase
  4ag M0 clause about "not being a rescue" and still be anti-
  validated by the forward-return record.

### 2.C Phase 4aj's reconciliation with Phase 4z / 4m / 4t

Phase 4aj concluded that:

- Phase 4ag's ten-clause M0 is a strict subset of the Phase 4z
  proposed admissibility framework (one upstream operationalized
  fragment, not the whole proposal);
- M0 complements (does not replace) the Phase 4m 18-requirement
  validity gate and the Phase 4t 10-dimension scoring matrix;
- the cleanest reconciliation is a lightweight upstream
  admissibility screen that complements existing governance
  layers without committing to the full Phase 4z 32-item framework.

### 2.D Operator authorization

The operator has now separately authorized Phase 4ak as a
**docs-only governance adoption phase** to make the revised
twelve-clause M0 gate and the post-null cooldown rule binding
prospective governance.

## 5. Binding M0 Gate

The twelve-clause binding M0 gate is recorded in the durable
governance document:

```text
docs/00-meta/m0-mechanism-admissibility-gate.md  (§5)
```

Summary of the twelve clauses (full text in the durable document):

- **M0.1** Mechanism source — name it; if price-only, justify why
  not in the depleted lane.
- **M0.2** Non-price-only or structurally distinct source —
  parameter / descriptor / interval / symbol-universe tweaks of
  failed families do not satisfy this.
- **M0.3** Baseline-superiority theory versus H0 and R3 — derive
  predicted Δ_R from theoretical content; commit to it as the
  expected baseline-test outcome.
- **M0.4** Rejection-topology distance — cover R2, F1, D1-A, V2,
  G1, C1, and any later-rejected strategies; name the closest-
  prior-failure trap; structurally distinguish.
- **M0.5** Cost-realism plausibility under §11.6 = 8 bps per side
  (round-trip 16 bps).
- **M0.6** Opportunity-rate plausibility — predeclared floors
  derived from theory, not from prior forensic numbers.
- **M0.7** Edge-rate plausibility — separate from opportunity-rate;
  predeclared baseline-differential floor with CI predicate or
  equivalent.
- **M0.8** Data availability and integrity feasibility — PASS /
  governed-partial / blocked classification; no acquisition implied.
- **M0.9** Governance compatibility — explicit conformance with
  §11.6, §1.7.3, Phase 3r §8, Phase 3v §8, Phase 3w §6 / §7 / §8,
  Phase 4j §11 if applicable, Phase 4k / 4p / 4q / 4v / 4w if
  adjacent.
- **M0.10** Forbidden-rescue and anti-reduction check — name
  closest rescue trap; structural distinction required.
- **M0.11** Pre-backtest falsification criteria — predeclared
  descriptive evidence that would kill the candidate before any
  backtest grid budget is spent.
- **M0.12** Post-null cooldown and non-authorization — check
  cooldown status; passing M0 does not authorize any successor
  phase.

## 6. Binding Post-Null Cooldown Rule

The post-null cooldown rule is recorded in the durable governance
document:

```text
docs/00-meta/m0-mechanism-admissibility-gate.md  (§6)
```

Summary: after a predeclared feasibility phase returns
`NOT_SUPPORTED`, the same mechanism family may not be re-opened
through descriptor / parameter / threshold / symbol-universe /
interval / forward-horizon / filter / composite-weight / rebalance-
frequency tweaks unless a future docs-only M0 memo first identifies
a **materially new mechanism source** that is independent of the
failed descriptor family. "Materially new" means derived from
external theory or external evidence, not from observation of the
failed phase's forensic results. The cooldown applies to the family,
not only to the specific candidate.

The current cooled-down families list at the Phase 4ak adoption
boundary is recorded in the durable governance document at §7. It
includes (in summary): price-only single-symbol directional
continuation (DEPLETED); cross-sectional trend / relative-strength
symbol-selection under Phase 4ai descriptors (COOLED_DOWN_AFTER_
NOT_SUPPORTED); derivatives-context directional lane (CONDITIONAL_
ONLY / HIGH_D1-A_RESCUE_RISK); microstructure / order-flow / liquidity-
timing lane (NOT_RECOMMENDED_NOW); mark-price stop-domain /
execution-realism lane (NOT_RECOMMENDED_NOW).

## 8. Required Future Use

After Phase 4ak:

- **Any future market-research lane must clear M0 before discovery
  / spec / backtest.** A future phase whose purpose falls within
  the durable doc §4.A applicability scope must produce an M0 memo
  using the durable doc §8 template (or a clearly-labeled
  superset).
- **Any reopening of cooled-down lanes must clear M0 and justify a
  materially new mechanism source** per durable doc §6.A. A future
  reopening proposal that does not satisfy §6.A is structurally
  inadmissible.
- **Passing M0 does not authorize backtests or strategy specs.** M0
  is an upstream filter. Strategy work, if it ever resumes, must
  also clear Phase 4m's 18-requirement gate, Phase 4t's 10-dimension
  scoring matrix (inside a discovery memo), and the existing
  per-phase strategy-spec / backtest-plan / execution-report
  requirements (Phase 4g / 4p / 4v; Phase 4k / 4q / 4w; Phase 4l /
  4r / 4x precedents). Each of those subsequent phases requires
  separate operator authorization.
- **Operator authorization is still required for every phase**,
  including the M0 memo itself for any future research lane.
  Phase 4ak does not implicitly authorize any future M0 memo.
